# Beginner guide

CampusConnect AI retrieves information from a small academic dataset. It does not learn or verify the policies of your college.

## Main files

- `backend/app/services/data_loader.py`: reads the supplied JSON and creates searchable records.
- `backend/app/services/faq_service.py`: builds and queries the TF-IDF baseline.
- `backend/app/services/retrieval.py`: loads the pretrained sentence embedding model and searches by cosine similarity.
- `backend/app/services/retrieval_engine.py`: selects TF-IDF, semantic, or hybrid ranking and uses TF-IDF if semantic search is unavailable.
- `backend/app/services/answer_builder.py`: formats a stored FAQ answer or fields from a retrieved record.
- `backend/app/main.py`: defines FastAPI routes, validates requests, and connects retrieval, feedback, PDF management, and analytics.
- `backend/app/database.py`: stores feedback, query analytics, and uploaded PDF records/chunks in SQLite.
- `backend/scripts/evaluate_retrieval.py`: evaluates the three retrieval methods on the separate BEC JSON benchmark and writes reports under `backend/reports`.
- `backend/scripts/predict_test_queries.py`: writes document-ID predictions for unlabelled test queries.
- `frontend/src/App.tsx`: React chat and knowledge-library interface.

## From JSON to a searchable document

Each JSON row keeps its original fields and `document_id`. The loader also records a category, source filename, and title. It converts available values into labeled text such as `department: Computer Science` and `subjects: AI, Data Science`. Nested objects and lists are converted to readable text. A row with no useful searchable fields is skipped rather than indexed using only a generic category label.

For an FAQ, the question and answer become searchable text. The answer builder returns the stored answer when that FAQ is retrieved. Other record types are formatted from their available fields. The assistant does not make up absent fields.

## What the evaluation labels do

`backend/data/retrieval_evaluation_queries.json` contains original FAQ questions, paraphrases, and unsupported or empty queries. Each answerable query is labeled with the expected FAQ ID, including stable IDs generated by the dataset loader when the source record has no ID. The expected ID is only used after retrieval to calculate Top-1, Top-3, and MRR; it is never passed into search.

The benchmark currently has 33 answerable queries and 8 rejection queries across 170 FAQs. It is manually prepared and small, so it is useful for regression checks but does not guarantee real-world accuracy. The separate CSV prediction script remains for the legacy academic retrieval corpus and is not the active BEC evaluation path.

## Three retrieval approaches

### TF-IDF

TF-IDF gives more weight to terms that are useful in a document and less weight to terms that occur everywhere. It converts each query and document into sparse number vectors, then cosine similarity ranks documents with overlapping language. It is fast and needs no network or model download, but can miss paraphrases.

### Semantic embeddings

An embedding is a list of numbers representing aspects of text meaning. Sentence Transformers loads the pretrained `sentence-transformers/all-MiniLM-L6-v2` model, encodes each document, then encodes the student's query. The app compares normalized vectors with cosine similarity. The document vectors are cached in memory for the backend process and rebuilt when the corpus text changes.

Cosine similarity is a ranking score, not a confidence probability. A larger score means the vectors point in a more similar direction; it does not prove that an answer is correct.

### Hybrid ranking

TF-IDF scores and embedding similarities have different scales, so the hybrid mode combines ranks rather than adding raw scores. Reciprocal Rank Fusion gives each result `1 / (k + rank)` for each search method and adds the contributions. This project uses `k=60`.

## From a question to an answer

1. The browser sends the query and selected retrieval mode to `POST /api/chat`.
2. The selected retriever returns ranked records with their document IDs and scores.
3. A relevance threshold can reject weak matches; no result produces the explicit unsupported-answer response.
4. The local answer builder formats the FAQ answer or factual fields from the record.
5. The response returns the answer and source metadata so the interface can show where the information came from.

An optional OpenAI-compatible LLM can rewrite a response using retrieved evidence, but no LLM key is required. The request includes the question and retrieved content, so external-provider costs and data handling should be considered. If the provider is not configured or fails, the local answer builder remains available.

Broad requests such as "What courses are available?" take a collection path instead of top-three retrieval. The API returns a page of records plus total count and a `has_more` flag. The UI's next/previous controls let the student access all records. Specific questions continue to use a small ranked set of relevant evidence.

## Running and checking the app

Create the Python environment and install backend requirements from the project root:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt
```

Copy `.env.example` to `.env` and `frontend\.env.example` to `frontend\.env.local` as described in the root README. The BEC dataset must be present locally; it is not included in Git while redistribution rights are unconfirmed.

Run the backend in one terminal:

```powershell
Set-Location backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Run the frontend in another terminal:

```powershell
Set-Location frontend
npm.cmd install
npm.cmd run dev
```

Open the frontend URL printed by Vite. The API health check is `/api/health`, and API documentation is `/docs` on port 8000. The first semantic search may download the pretrained model; TF-IDF remains available if that download fails. The frontend displays the last saved BEC evaluation report; it does not run evaluation for each visitor.

Run backend tests and refresh evaluation from the `backend` directory:

```powershell
..\.venv\Scripts\python.exe -m pytest tests -q
..\.venv\Scripts\python.exe -m scripts.evaluate_retrieval
```

Uploaded PDF listing, upload, and deletion require a private `ADMIN_API_KEY` in the backend `.env` and the matching `X-Admin-Key` request header. Do not place that key in frontend code.
